#  Todo REST API — Intermediate Assignment 4

This project is an implementation of an asynchronous REST API for managing a Task/Todo list, built using **ASP.NET Core Web API**. The project satisfies all mandatory assignment requirements, adhering to industry best practices for layered architecture, asynchronous non-blocking I/O flow, and HTTP correctness.

---

## Project Architecture & Structure

The application is split into logical layers to enforce a clean separation of concerns and ensure a seamless future transition to a SQL database:

* **`Model/`**: Contains the domain object (`TodoItem`) equipped with robust data validation using `DataAnnotations`.
* **`Services/`**: Encapsulates business logic and data access. By utilizing the `ITodoService` interface, the controller is completely decoupled from the data storage mechanism.
* **`Controllers/`**: Manages incoming HTTP requests, performs validation at the HTTP layer, and returns semantic HTTP status codes.

## API Documentation & Endpoints

### 1. Get All Tasks (With Filtering & Pagination)
Retrieves a paginated list of todo items, with optional status filtering.

* **HTTP Method:** `GET`
* **Route:** `/api/todo`
* **Query Parameters:**
    * `isCompleted` *(bool, optional)*: Filter by completed (`true`) or active (`false`) tasks.
    * `page` *(int, default = 1)*: The page number to retrieve.
    * `pageSize` *(int, default = 10)*: Maximum number of items per page.
* **Example Request:** `GET /api/todo?isCompleted=false&page=1&pageSize=2`

#### Example Response (200 OK):
```json
[
  {
    "id": 1,
    "title": "Levere C# Oppgave",
    "description": "Laste opp github-link på canvas",
    "isCompleted": false,
    "createdAt": "2026-06-01T21:05:33.3465745Z",
    "dueDate": null
  }
]

```

### 2. Get Specific Task

Retrieves the details of a single task by its unique identifier.

* **HTTP Method:** `GET`
* **Route:** `/api/todo/{id}`
* **Error Handling:** If the specified ID does not exist, it gracefully returns a `404 Not Found` with a descriptive JSON message.

#### Example Error Response (404 Not Found):

```json
{
  "message": "Oppgave med ID 99 ble ikke funnet."
}

```

### 3. Create a New Task

Creates a new resource. The endpoint automatically validates inputs to ensure requirements (e.g., non-empty title) are met.

* **HTTP Method:** `POST`
* **Route:** `/api/todo`
* **Payload (Request Body):**

```json
{
  "title": "Levere C# Oppgave",
  "description": "Laste opp github-link på canvas",
  "isCompleted": false
}

```

#### Example Response (201 Created):

*Note that `id` and `createdAt` are automatically generated by the backend service.*

```json
{
  "id": 1,
  "title": "Levere C# Oppgave",
  "description": "Laste opp github-link på canvas",
  "isCompleted": false,
  "createdAt": "2026-06-01T21:05:33.3465745Z",
  "dueDate": null
}

```

* **Response Header:** Includes a `Location: http://localhost:5000/api/todo/1` header pointing directly to the newly created resource.

## ⚙️ Database Configuration & SQL Support (Optional Requirement)

The application currently utilizes an **In-Memory collection** (simulated asynchronously using `Task.Delay`), but the architecture is 100% prepared to integrate with **Entity Framework Core**.

### To switch to SQL Server or SQLite:

1. Install the required package:
```bash
dotnet add package Microsoft.EntityFrameworkCore.SqlServer

```


2. Define your connection string in `appsettings.json`:
```json
"ConnectionStrings": {
  "DefaultConnection": "Server=(localdb)\\mssqllocaldb;Database=TodoDb;Trusted_Connection=True;"
}

```


3. Execute database migrations in your terminal:
```bash
dotnet ef migrations add InitialCreate
dotnet ef database update

```

## 🚀 How to Run and Test the Project Locally

### Prerequisites

* [.NET 8.0 SDK](https://dotnet.microsoft.com/download) or newer installed (.NET 10.0 supported).

### Compilation & Running

1. Open your terminal in the project root directory (`TodoApi/`).
2. Build the project to verify dependencies:
```powershell
dotnet build

```


3. Run the compiled application binary natively to avoid local OS execution environment permission blocks:
```powershell
dotnet bin\Debug\net10.0\TodoApi.dll

```


The terminal will log that the application has started: `Now listening on: http://localhost:5000`.

### Testing the Endpoints

#### Test GET via Web Browser

Open your browser and navigate to:

```text
http://localhost:5000/api/todo

```

It should return a JSON array containing your tasks (or an empty array `[]` if no tasks have been created yet).

#### Test POST via PowerShell

To add data to the system, open a new PowerShell window and run the following commands to send a clean JSON payload:

```powershell
$body = @{
    title = "Levere C# Oppgave"
    description = "Laste opp github-link på canvas"
    isCompleted = $false
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:5000/api/todo" -Method Post -ContentType "application/json; charset=utf-8" -Body $body

```

* **HTTP Correctness:** Implements semantic verbs (`GET` for safe reading, `POST` for creation returning `201 Created` with a `Location` header).
